# Развитие ScopeWatch

Цель: надёжные и полезные уведомления об изменениях разрешённого scope.

## Уже в Go-версии

- Изолированные адаптеры Standoff и BI.ZONE.
- `status` / `status --json`: свежесть данных, сбои, размер очереди.
- Исключение конкурирующих прогонов, отмена запросов при остановке.
- Защита от неполных страниц, частичных сбоев и ложных удалений.
- SQLite, транзакционная очередь и E2E через настоящий бинарник.

## Следующие приоритеты

| Приоритет | Изменение | Польза и условия готовности |
| --- | --- | --- |
| 1 | Фильтры уведомлений | Выбор площадок, программ и типов событий; фильтровать отправку, сохраняя полную историю |
| 1 | История одной программы | Команда `diff --program ... --since ...`; хранить версии снимков с ограничением срока/объёма |
| 1 | Предупреждение об устаревших данных | Порог возраста успешного снимка, включая отсутствие прогонов; внешняя проверка нужна, если сам сервис остановлен |
| 2 | Сводка мелких правок | Новые ассеты/изменение выплат сразу, редакционные изменения текста — в дневную сводку; расписание и часовой пояс задаются явно |
| 2 | Webhook | Версионированная схема событий, HMAC-подпись, event ID и отдельная очередь для каждого получателя |
| 2 | Метрики | Время и результат сборов, возраст снимка, доля ошибок, размер и возраст очереди; без токенов и scope в метках |
| 3 | Новые платформы | Официальный API или разрешённый публичный источник, реальные фикстуры и проверка полноты пагинации |

## Что не стоит усложнять сейчас

Микросервисы, отдельный брокер, динамические плагины, обязательный веб-интерфейс
и параллельные запросы к десяткам страниц не решают текущие задачи лучше
одного процесса с SQLite. Добавлять их стоит по измеренной потребности.

Автоматическое ранжирование важности текста полезно лишь после появления
размеченных примеров. До этого лучше явные категории событий и фильтры.
