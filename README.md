# scope-watch

Следит за публичными bug bounty программами **Standoff 365** и **BI.ZONE** и пишет в Telegram, когда:

- 🆕 появилась новая программа;
- 🎯 в скоупе появились новые ассеты: домены, wildcard, IP, мобильные приложения. Они идут блоком `<pre>`, чтобы сразу скопировать в subfinder/httpx;
- 🚫/✅ что-то добавили в out of scope или убрали оттуда;
- 💰 изменились выплаты;
- 📝 поменялся текст скоупа или правил (короткий дифф);
- 🔒/♻️/🗑 программа закрылась, переоткрылась или пропала из публичного списка;
- 🗂 на BI.ZONE вышла новая версия правил или выплат.

## Запуск (Docker)

```bash
git clone git@github.com:khunzzz/scope-watch.git && cd scope-watch
cp .env.example .env              # TG_BOT_TOKEN и TG_CHAT_ID
mkdir -p data && sudo chown 1000:1000 data
docker compose up -d --build
docker compose logs -f
```

Первый прогон (~3 минуты) только сохраняет базу и шлёт 🌱. Дальше проверка идёт каждые 15 минут (`SCOPEWATCH_INTERVAL`).

Как получить токен и chat_id: @BotFather → `/newbot` → токен, затем напиши боту `/start`. Команда
`docker compose run --rm scope-watch scope-watch test-notify` без `TG_CHAT_ID` покажет id чатов, которые писали боту, а с ним пришлёт тестовое сообщение.

Перед деплоем проверь, что площадки открываются с IP сервера:
`curl -sI https://bugbounty.bi.zone/api/bug-bounty/companies/ | head -1`.

Полезные команды (`docker compose exec scope-watch scope-watch <команда>`):

| команда | что делает |
|---|---|
| `history [-n 50] [--program tbank]` | журнал изменений из базы |
| `links` | какие программы склеены между платформами |
| `export -o /data/companies.json` | сводный скоуп по компаниям без дублей (для рекона) |
| `run --dry-run` | прогон с печатью сообщений, ничего не сохраняет |

## Как это работает

Каждые 15 минут: **собрать** обе площадки → **сравнить** с базой → **склеить** компании между площадками → **отрендерить** (одно сообщение на компанию) → **отправить** → **сохранить**. Сначала идёт отправка, потом сохранение: если Telegram недоступен, события придут в следующий прогон.

### Откуда берётся скоуп

| | Список | Скоуп | Выплаты |
|---|---|---|---|
| BI.ZONE | `/api/bug-bounty/companies/` | **структурированный**: `/api/bug-bounty/tasks/`, у каждой группы есть флаг in/out of scope, хосты лежат в её описании | `min/max*Price` |
| Standoff 365 | `__NEXT_DATA__` страниц `/programs?page=N` (с `Accept-Language: ru`, иначе приходит машинный перевод) | **из текста** `description` + `specialRules`, см. ниже | `pageProps.reward`, перезапрос при смене `updatedAt` или раз в 6 ч |

### Извлечение ассетов из текста (Standoff)

Структурированного скоупа Standoff анонимно не отдаёт, поэтому домены извлекаются из markdown. Это эвристика, но с двумя страховками:

1. **Отслеживается и сам текст.** Любая правка скоупа придёт как 📝-дифф, даже если экстрактор что-то не распознал. Событие не теряется, в худшем случае неточным окажется список ассетов.
2. **Экстрактор выверен на реальных данных** (153 активные программы, ~1900 ассетов):
   - доменная зона проверяется по полному списку IANA, поэтому `boot.ini`, `т.д`, `window.opener`, `user6.rules` отсекаются, а `youdrive.today`, `пример.рф` проходят;
   - понимает wildcard где угодно (`*.x.ru`, `videostun*.okcdn.ru`, `call*-*.vkuser.net`), записи вида `*.vkontakte.(ru|com)`, markdown-ссылки `*.[tbank.ru](…)`, экранирование `\*.x.ru`;
   - приложения: ссылки на Google Play / App Store / RuStore / AppGallery, в том числе без `https://`, и package id текстом (`ru.tinkoff.investing`);
   - **учитывает разделы**: всё под заголовками «НЕ искать», «Вне области», «Out of scope», «Исключения», «Не принимаем» (и в их подразделах) уходит в out of scope, а не в «новые ассеты»;
   - выкидывает приватные IP, e-mail, справочные сайты (owasp, mitre…) и ссылки на саму площадку, кроме программы самой площадки.

Без ассетов остаются ~20 программ, у которых в тексте нет доменов: продукты PT/MaxPatrol (ПО, а не сайты) и программы с недопустимыми событиями. По ним работает только дифф текста.

### Дубли между площадками

Многие компании есть на обеих: VK, Т-Банк, Ozon, Госуслуги, Timeweb, RuStore, Kuper… (сейчас склеено 29 пар). `linker.py` склеивает их по общим регистрируемым доменам и id приложений. У каждого признака вес 1/частота, поэтому `mail.ru` из правил всех VK-программ почти ничего не весит. Ещё учитывается нормализованный slug (`vkplay_vk` ↔ `vk-play`), и связь ставится только при взаимном выборе. Что это даёт:

- одно сообщение на компанию, даже если она обновилась на обеих площадках;
- новые ассеты делятся на «действительно новые» и «уже были в скоупе на другой площадке»;
- «🔗 Также на …» со ссылкой.

### Защита от ложных срабатываний

| ситуация | поведение |
|---|---|
| первый запуск, пустая база | сохраняет и шлёт одно 🌱, без сотни «новых программ» |
| площадка не ответила / 5xx | ретраи; при неудаче данные площадки не трогаются; ⚠️ после 3 провалов подряд, ✅ при восстановлении |
| список пришёл сильно короче (−30% и больше 5 программ) | считается сбоем, ложных 🗑 нет |
| программа выпала из списка один раз (сдвиг пагинации) | молчим; 🗑 только если её нет 2 прогона подряд |
| площадка поменяла формат, изменилось >30% программ разом | одно сводное ⚠️ вместо сотни сообщений |
| обновился сам экстрактор (`assets.VERSION`) | ассеты старых снапшотов не сравниваются, текст сравнивается |
| у Standoff не загрузились выплаты | не считается изменением выплат |
| `docker stop` посреди прогона | прогон дописывается (`stop_grace_period`), запись в SQLite атомарная |

### Чего не видно

- приватных программ и всего, что за логином;
- скоупа во вложениях (PDF/картинки) и на внешних страницах, куда ссылается программа;
- изменения выплат на Standoff — с задержкой до 6 часов, если площадка не обновила `updatedAt`.

## Хранилище

Один файл SQLite `data/scope-watch.db`:
- `programs` — текущее состояние;
- `changes` — журнал всех изменений (`scope-watch history`);
- `health` — счётчики сбоев площадок.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest                       # тесты на реальных фикстурах, без сети
.venv/bin/scope-watch seed             # без токена печатает в консоль; база в ./data
.venv/bin/scope-watch run --dry-run
```

```
scopewatch/
  cli.py        loop / run / seed / history / links / export / test-notify
  config.py     Settings из env / .env
  runner.py     прогон: collect → diff → link → render → send → save
  sources/      по модулю на площадку: fetch(client, prev) -> list[Program]
  assets.py     извлечение ассетов, разбивка in/out of scope, registrable(), covered()
  tlds.py       список зон IANA
  differ.py     состояния → структурные изменения
  linker.py     склейка компаний между площадками
  render.py     изменения → HTML для Telegram
  notify.py     Telegram Bot API / stdout
  storage.py    SQLite
```

Новая площадка — это модуль в `sources/` с `NAME`, `TITLE`, `fetch()` и строка в `sources/__init__.py`.
