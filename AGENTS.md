# Работа с scope-watch

## Назначение и устройство

Go CLI для мониторинга публичных bug bounty программ Standoff 365 и BI.ZONE.
Сервис собирает снимки, сравнивает scope, правила, выплаты и статусы,
связывает программы компаний и отправляет изменения в Telegram.

- `cmd/scope-watch`: точка входа и сигналы завершения.
- `internal/app`: Cobra CLI, настройки, HTTP-политика, сборы и блокировка.
- `internal/adapters/{standoff,bizone}`: загрузка и разбор данных площадок.
- `internal/scope`: модели, извлечение ассетов, сравнение и связи программ.
- `internal/storage`: SQLite, схема и транзакционная очередь уведомлений.
- `internal/notify/telegram`: HTML-сообщения и Telegram Bot API.
- `e2e`: настоящий бинарник, локальный HTTPS-прокси и фикстуры `testdata`.

Подробности запуска и контракта адаптеров — в `README.md`.

## Правила изменений

- Сначала изучить затрагиваемый путь выполнения и существующие E2E-сценарии.
- Делать небольшие обоснованные изменения; не добавлять инфраструктуру без задачи.
- Использовать версию Go из `go.mod`; согласовывать изменения с Dockerfile и CI.
- Применять `gofmt`. Цепочки SQL-запросов писать с вызовом метода на строку.
- Сохранять отмену через context, таймауты, ограничения размера HTTP-ответов,
  правила редиректов и маскирование Telegram-токена.
- Не выводить секреты, не коммитить `.env`, `secrets`, рабочие базы и экспорты.
- Не запускать реальные Telegram-отправки и сборы без необходимости задачи;
  проверки выполнять через локальные фикстуры и временные каталоги.
- Адаптер не изменяет предыдущий снимок. Неполный список или обязательный scope
  не должны заменять корректные данные и вызывать ложные удаления.
- Снимки, история, здоровье площадок и очередь фиксируются одной транзакцией.
  Сообщение удаляется из очереди только после успешной доставки в Telegram.
- Сохранять межпроцессную блокировку и семантику dry-run.
- При изменении извлечения ассетов пересматривать `ExtractorVersion`,
  чтобы обновление парсера не создавало ложные уведомления.
- Для исправлений поведения добавлять регрессионные E2E-проверки;
  не ослаблять TLS и не добавлять тестовые обходы в рабочий код.
- Изменения команд и настроек описывать в README.

## Проверки

```sh
gofmt -w cmd internal e2e
go mod verify
go vet ./...
go test -race -count=1 ./e2e
CGO_ENABLED=0 go build -trimpath -o bin/scope-watch ./cmd/scope-watch
```

Для race-проверок нужен C-компилятор. Обычная сборка работает без CGO.
CI также запускает govulncheck и проверяет Docker-образ.
В результате работы указать изменения, выполненные проверки и их ограничения.
Не отправлять коммиты в удалённый репозиторий без запроса пользователя.
